# teach-me / 伴随式 AI — 设计要点（2026-10-15）

讨论记录，供后续继续聊或交给开发。未定事项单独标出。

## 产品定位
- 更准确叫「伴随式 AI」；教学是其中一种用法。
- 只指不做：画在真实界面上，不代替用户点击。
- 参考：Arin（只画不点、TTL）、big-arrow（大箭头穿透点击）、现有 teach-me 仓库。

## 已定：输入（用户 → agent）
- **输入与画板分离**（功能层面：画板内容只作为可选附件，开关收在输入区内；**不做两套 UI**）。
- **始终一个窗口、一个输入面：面板内的输入胶囊。** 不新开窗口。
- **两种输入：语音、文字。** 共用一个入口：
  - **按住** = 语音（按住说，松开发送）
  - **单击** = 文字（焦点落到面板内输入胶囊，回车发送；发送后焦点还给当前软件）
  - 收起态与展开态**共用同一个输入胶囊**（收起时它就是那条「胶囊」，展开时它吸在面板底部）。
- **截图时机：**
  - 语音：在**开始说话时**截（不是松手时）
  - 文字：在**输入区拿到焦点之前**截（此时我们的窗口仍是隐藏的，不会截到自己）
- **语音确认：** 识别结果闪现约 1–2 秒，期间可撤回；不强制每次确认。
- **发送时可选择是否附带画板内容**；画板有内容时默认勾选。

## 已定：画板
- 画板常驻；平时点击穿透，进入**编辑模式**才画画。
- 用户层 / agent 层分数据、同画布显示（颜色/样式区分）。
- 可分别清除用户笔迹 / agent 指引。
- 开源方案可考虑 Excalidraw / tldraw（实现选型，非交互结论）。

## 已定：agent 截屏
- 三档：每次询问 / 本次教学默认允许 / 始终允许。
- **每次询问：** 直接出审批气泡（不先读秒）。
- **默认允许：** 边缘短读秒 → 到点自动截；读秒中快捷键打断 → 回到待审批。
- 审批**不能抢键盘焦点**；点击穿透 + 快捷键批准。
- 截前短暂隐藏 agent 指引，避免截进自己的画。

## 已定：指引（屏幕上）
- 三层：固定范式 → 基础图元组合 → 完全自由（HTML/动画）。
- 风格仅 **skill/提示词软约束**；安全硬约束：点击穿透、不联网、可统一清。
- **失效：** 用户清除，或 agent 在拿到新状态、下次询问前自行清除（不做滚动自动失效）。

## 已定：悬浮窗
- 默认**收起**；agent 新 `say` 时自动展开，悬停时不收。
- 只能显示 agent 经协议发来的内容（最新 `say` ≠ 模型全文）；skill 约束每次 show 带短 say。
- 桌宠：app **自带**形象，与「简洁胶囊」二选一；agent 只驱动状态，不换皮。

## 已定：会话
- 屏幕上**单例活跃会话** + 每会话 **唯一 id**。
- agent **拉起 app** 的那次：**免同意**。
- 其它 agent 连接：**需用户决策**；已有活跃会话时默认拒新连。
- 不做第一版「挂起恢复」；用户说「等一下」只是节奏暂停。

## 已定：设置页（v1 范围）
1. 快捷键  
2. 输入与语音  
3. 隐私与截屏  
4. 外观（含桌宠/胶囊、自动收回时长等）  
5. 会话（session id + 复制按钮；诊断用，故从面板挪来此处）  
- **不做**连接类设置；对外给 session id，各 agent 自行连接。
- 含「再看一次引导」。

## 已定：首次引导
- 内置 **fake agent**，走真实协议带 3 步：输入 → 画板 → 隐藏指引。
- 触发：首次启动；设置「再看一次引导」。
- 可跳过。

## 搁置 / 未决
- agent **宿主**命令审批如何露到面板（先不管）。
- 多显示器布局。
- 出错与异常的完整文案（断线已有方向：提示断开，指引稍后清）。

- **状态行与芯片打架（2026-10-16 发现）：** `session.agentState()` 只返回 `ended / listening / thinking / offline`，**没有「已连接且空闲」这个值**，于是 agent 空闲时状态行写「agent 还没连上」，而同一时刻 `#offer` 芯片又浮出来说「下一步呢？」—— 两句互相矛盾。修法二选一：给 `agentState()` 补 `idle`（语义最准，但要动 session 的核心判定），或面板在 `offline && pending === 0 && 已有历史` 时把文案换成「轮到你说了」（UI 层可解，零风险）。

## 补充决议（20:09–21:31）
- **快速推进：** 面板空闲（agent 不在听 / 不在想）且已经说过话时，对话流底部浮出一枚 `下一步呢？` 芯片；点它 **＝以用户身份发一条普通消息**（`source: 'continue'`，和打字、说话同一条链路），用户一开始打字或说话它就消失。可绑独立快捷键（默认空）；打字仍走单击输入入口（即面板内胶囊）。强调键盘操作，避免鼠标抢焦点打断菜单等操作。
- **用户发消息附带截图：** 默认附带，设置里可关闭。用户主动发送的截图不需要再审批。
- **agent 截图失败：** 有限次自动重试，不能无限重试。
- **高分屏/缩放：** 必须处理。agent 只按截图像素给坐标，app 按截图时记录的该屏缩放比例与位置换算；画面或缩放变化时轻提示并重新截图。
- **多显示器：** 开始教学时让用户选一块屏。
- **隐私：** 按现仓库现状。
- **虚拟显示器：** 系统能识别的就当普通显示器，进选屏列表并按其缩放换算；截不到或拿不到缩放信息的标“不支持”不可选；教学中途断开则暂停指引、在主屏提示重新选屏或结束。

## 补充决议（2026-10-16）：单一输入面

**背景：** 原设计里「单击 = 弹出独立输入窗」，落地后出现两个问题 ——
1. 收起态的状态行文案与弹出窗的占位文案**重复**（都在说同一句「说一句」）；
2. 多一个窗口 = 多一次焦点搬运、多一套样式要跟着 token 走，且与「面板本身就是那条胶囊」的观感冲突。

**决议（用户拍板）：** **一个输入框够了 —— 始终一个窗口。**
- `input` 独立窗口**整体取消**（`app/ui/input.html`、`app/ui/input.js` 已移出，归档在 `app/ui/_retired/`）。
- 面板 `#composer` 成为**唯一**输入面：收起态它就是那条 capsule，展开态吸在面板底部；同一份 DOM、同一份焦点逻辑。
- 保留的行为：截图仍在**拿到焦点之前**完成（`grabFrame()` 会隐藏我们所有窗口）；取消（Esc）与空发送后把焦点还给原前台窗口。
- 键盘走 `input:submit` / `input:cancel` / `input:pointer` 三个既有 IPC 通道，主进程不再持有 `inputWin`。
- 「输入与画板分离」按**功能**理解：画板附件开关（`.toggle` / `#attach-board`）住在输入胶囊内部；语义上仍是两件事（说话 vs. 附一张图），只是不再各占一个窗口。

### 头部那一行的取值优先级（补记）

**两态共用同一个槽位、同一条规则。** 独立的 `#status` 状态条已整体取消，它的职责并入头部那一行 `#last`。

| 优先级 | 来源 | 说明 |
|--------|------|------|
| 1 | 实时语音转写 `liveText` | 按住说话期间，边说边显示（取 `--ok` 绿） |
| 2 | agent 最近一句 `lastLine` | 有 `say` 就以它为唯一权威（仍是「只显示 agent 发来的内容」） |
| 3 | app 自身状态文案 `statusText` | 只在**两者都没有**时兜底（「还没有教学」「agent 还没连上」等），灰或黄 |

`no-last` class 标记「当前显示的是第 3 档兜底」（`!liveText && !lastLine`），CSS 据此上灰（`body.no-last:not(.thinking) #last`）或黄（`body.no-last.thinking #last`）；有真内容时不加该 class，走默认文字色。listening 期间 `liveText` 非空，所以 `no-last` 为假、`body.listening #last` 单独给绿色。

这里对 L54「只能显示 agent 经协议发来的内容」做一处**收窄解释**：那条约束管的是**不能伪造/透传内容**（不能显示模型全文、不能显示未经 `say` 的东西）。用状态文案兜底是**本地状态位**、不是内容，故允许；一旦有 agent 内容或转写，状态文案立即让位。

## 补充决议（2026-10-16）：展开态排布

**原则：按职责分层，一层一件事。** 落地为四层，自上而下：

| 层 | 装什么 | 规矩 |
|----|--------|------|
| **1 标题栏**（一行） | `●` 状态点 + `#last` 一行 ‖ `⚙` `✕` | 点与它的文字**同行**；右侧只放**窗口级**动作（设置、结束） |
| **2 对话**（`flex:1`） | 空态 / 线程 | 唯一会伸缩的一层 |
| **3 建议 chip** `#offer` | 「下一步呢？」 | 贴输入胶囊上沿；只出在展开态 |
| **4 输入胶囊** `#composer` | 输入框 + 工具行 | 唯一输入面，收起态就是它本身 |

### 状态条并入标题栏

原 `#status` 是独立一条横带（32px），把「状态点」与「状态文字」拆到了两处，中间还隔着头部动作行。并入标题栏后：

- 展开态：**头部 85px → 50px**、**去掉 `#status` 32px**，合计省 **67px**；
- 对话区从 **268px（48%）** 升到 **393px（70%）**。

### `#foot` 工具栏拆解

原 `#foot` 是一条常驻横带（50px），装四个低频动作。现按「该不该常驻」分开处置：

| 原动作 | 去处 | 理由 |
|--------|------|------|
| 清笔迹 | 输入行，**按需出现** | 只在 `board.user.length > 0` 时显示 |
| 清指引 | 输入行，**按需出现** | 只在 `board.agent.length > 0` 时显示 |
| 指引显隐（眼睛） | 输入行，**按需出现** | 只在有 agent 墨迹时才有可隐藏的东西 |
| 会话 ID + 复制 | **设置页** | 诊断用，不需要常驻在教学界面 |

**按需出现不新增任何 IPC**：`board.snapshot()` 下发的就是 `user` / `agent` **数组本身**（不是布尔），面板直接算长度即可。判据落在 body class `has-user-ink` / `has-agent-ink` 上，CSS 据此显隐；**看得见按钮本身就是读数** —— 见到「清笔迹」即代表你的笔迹还在。

「清指引」手动按钮只在一种场景有意义：讲完这一段、想马上清掉继续教（其余时机 `clearAgent()` 已自动执行：新课程开始、引导结束、教学屏断开）。

### 建议 chip 的位置

`#offer` 曾经被 `#foot` 整条工具行**挤在输入框之外**（DOM 顺序 `#log → #offer → #foot → #composer`）。工具行拆解后，chip 行直接贴住输入胶囊上沿。

依据：**建议动作属于输入侧，不属于消息流**（WorkBuddy / Claude / ChatGPT 桌面版同构）。`#offer` 与输入胶囊间距收到 2px + 8px。

## 补充决议（2026-10-16）：快捷键提示只做 tooltip

**决定：面板里不放常驻的提示行；快捷键只出现在 hover 的 tooltip 里。**

判据：快捷键提示是**学会一次就不再看**的信息（training-time），而对话历史是每次都用（runtime）。把前者放进后者占的大块视觉位置，就是说明书式布局 —— 与「空态不该是说明书」是同一条判据。业界同样把它降到边缘（Raycast AI 放底部一行，kit 设计系统的 `HintBar` 规定放页脚，Cluely 整个项目以「注意力预算」为中心约束）。面板已定为四层、每层职责明确，用**零高度**的 tooltip 承载比再占一行更合算。

| 元素 | tooltip | 键位来源 |
|------|---------|----------|
| `#entry`（麦克风） | 按住说话，点一下打字 | `hotkeys.talk` |
| `#btn-board` | 画板编辑：在屏幕上圈给它看 | `hotkeys.boardEdit` |
| `#offer`（chip） | 不用打字，直接让它往下讲 | `hotkeys.continue` |
| `#btn-eye`（指引显隐） | 隐藏 / 把指引显示回来（随状态翻转） | `hotkeys.toggleOverlay` |

- **未绑定就不写键**：`continue` / `boardEdit` 默认是空串，此时 tooltip 只留文字，不出现空括号。
- **accelerator → 人话**：主进程下发的是 Electron accelerator（`Control+Alt+W`），面板统一翻成 `Ctrl+Alt+W`（`Control` / `CommandOrControl` → `Ctrl`，`Meta` / `Super` → `Win`）。
- **空态是唯一例外**：它是「怎么开始」那一屏，`[data-hk]` 占位符由 `paintTips()` 从 live config 填真值。此前是硬编码，改了设置就会漂移 —— 那是 bug，不是特性。
- **不做**：不在历史下方加常驻 hint 行；不为提示新增任何 IPC（`panel:config` 本就带 `hotkeys`）。

## 补充决议（2026-10-16）：展开态窗口高度自适应

**决定：展开态窗口高度跟着内容走，夹在 `240 ~ 560`；收起态仍是固定胶囊。**

背景：写死 `520×560` 时，空态内容约 250px，剩下 300px 全是空白，看着像「没加载完」；两三条消息的会话也照样占满 560。

| | 收起态 | 展开态 |
|---|---|---|
| 谁决定高度 | 输入框（textarea 自动高） | 面板内容 |
| 通道 | `panel:composer-h`（增量，上限 120） | `panel:content-h`（绝对高） |
| 主进程 clamp | `136/148 + extra` | `PANEL_MIN_H 240` ~ `PANEL_MAX_H 560` |

- **测量方法**：`body` 是 `height:100%`、`#log` 是 `flex:1`，两者都被窗口拉伸，直接读不出内容高。`measureContent()` 在同一帧内临时放开二者（`height:auto` / `flex:none`），读 `body.offsetHeight`（含 1px 边框）后立刻还原 —— 浏览器只绘制最终状态，不会闪。
- **触发**：固定行（`#header` / `#flash` / `#tourbar` / `#offer` / `#composer`）用 `ResizeObserver` 观察；`#log` 是 `flex:1`，**故意不观察**（否则每次窗口 resize 都会乒乓一次上报），改在 `addAgent` / `addUser` / `addNotice` / `renderHistory` 里显式上报。上报按 `requestAnimationFrame` 合帧。
- **clamp 在主进程**：那是持有窗口的一方；面板报什么数都不会让窗口变成 0 高或跑出屏幕。
- **底边锚定**：`applyPanelBounds()` 用 `panelAnchorBottom` 让底边不动，高度变化时窗口向上生长。

**真机需确认**：首次 `panel:init` 到首次上报之间，窗口会以 560 高显示一帧再收到实际高度。若肉眼可见跳动，把首次测量改为不走 rAF 即可。
