# T16 · mini 输入面与位置记忆

日期：2026-10-18。环境：Windows，Electron 44.7.2，主屏 1707×960 DIP、150% 缩放。

实现：360 DIP mini、520 DIP 展开；唯一输入组件、多行自适应、更多工具；标题区 Pointer Capture 拖动，主进程约束和持久化位置。模式标记丢弃旧 resize，drag id 丢弃结束后的旧移动。

## 自动验证

- `npm run check`：规划、边界、格式、44/44 测试、类型及生产构建通过。新增三个纯几何案例覆盖锚点、负坐标/失效位置和小工作区。
- `node scripts/mini-panel.mjs`：两次启动通过。实际 DOM 无裁切；更多工具增高/恢复；多行输入、展开与收起保留相同 textarea、草稿和选区；受限拖动 IPC 持久化且旧回调不再移动；旧模式尺寸报告无效；重启恢复位置。
- `node scripts/smoke.mjs`：24/24 通过，包含输入/Enter/CLI 两轮收发、截图失败恢复、稳定 HWND/PID/任务栏样式及 HTML 隔离。
- `node scripts/board-smoke.mjs`：13/13 通过，编辑器、工具、清理与附画板发送无回归。

隔离测试不会读取真实桌面截图或更改用户配置。应用内部截图只留 `.runtime/mini-panel`。构建仍有 Excalidraw 分块体积提示，无构建错误；失败截图与 sender 拒绝日志为测试故意注入的拒绝路径。

## Windows 现场观察

使用 computer-use 原生鼠标：空态宽 360、高 74 DIP，工具图标与输入可见。起点 x1248/y739，拖动标题后 x1088/y744，HWND 始终为 5638746；本地保存 right1448/bottom818（Windows 四舍五入容许 1 DIP）。点击展开后宽520，右下锚点不变；展开态再次拖动到 x768/y521，并被工作区底边限制，锚点保存 right1288/bottom905；收起后 x928/y831、360×74，仍是同一 HWND。

初次 CSS app-region 原生拖动测试失败：有 hit-test 区域但鼠标拖动无窗口移动。改用受限手势 IPC 后上述移动成立；不把 CSS 样式断言当成真机通过。

停止隔离实例后，以真实拖动保存的 right1288/bottom905 直接重启，窗口恢复为 x928/y831、360×75 DIP（DPI 舍入），断言通过。该重启与之后重置配置的自动夹具分开执行。

## 限制

跨显示器/不同 DPI、断屏实际拖动尚未验证；纯几何负坐标和小工作区测试不能替代它们。原生输入区点击已到 editing，但电脑工具暴露的焦点仍为 RootWebArea，未继续盲打；真实键盘选区拖动单独保留 pending，自动草稿/选区与 Enter 回归不替代此项。其他 T10/T12/T14 的未完成验收不因这次 UI 调整而变更。
