# T31 发送已提交后焦点恢复失败 — 提交进展

2026-10-20，Windows、Electron44.7.2、Node24.19.0，基于27bd116；隔离数据在.runtime。

- 原因与复现：InputController把deliver与restore放同一try。投递已成功但restore拒绝会重新开放旧turn；Session按clientId去重，修改重试稿被忽略。旧版新增11项输入测试中2项失败；旧真实Electron界面故障注入也未出现已发送反馈并超时失败。
- 修复：投递成功不回滚，restore拒绝仅显示“消息已发送，但未能恢复原窗口焦点。可以继续输入。”；晚错误不覆盖新turn，旧turn不可重试。真正deliver失败保留原turn与原截图。
- 独立审查发现相邻问题：发送回包来得晚时，Panel无条件清稿/blur会丢掉新编辑。真实IPC夹具延迟已完成submit的回包，期间prepare新turn并输入新稿；旧版失败。修复为按草稿版本清理并检查当前turn后才blur，保持原单一输入面。
- 自动验证：`node --test test/input.test.ts` 11/11；`node scripts/delivery-smoke.mjs` 实际Renderer发送、故障注入、已发送提示、清稿、wait/ack、新turn第二条消息、延迟旧回包后的新稿/焦点/turn以及后续实际入队均通过。
- Windows原生观察：`node scripts/delivery-smoke.mjs --interactive`，computer-use点击输入，键入first message并Enter；现场看见第一条历史消息、空草稿和明确已发送/焦点警告。再次点击输入、键入next message并Enter，夹具确认两条消息分别收取/ack，成功退出。此轮是原生字符注入，不是中文IME验收；故障为真实宿主注入拒绝，不声称复现系统自发焦点故障。之后新增草稿版本保护由实际Renderer延迟回包回归验收。
- 相邻回归：`node scripts/dogfood.mjs --verify` 5组通过（连接帮助、历史阅读、长稿可达、设置草稿保护、跨窗口外观/画板）；控制台设置/权限错误是既有故障注入。`npm run check`通过，71测试/边界/格式/类型/构建，保留既有大chunk警告。
- 独立复审未发现阻塞问题；原生焦点是否成功由平台原场景继续验证，不把拒绝处理测试扩大为所有外部应用焦点验收。
