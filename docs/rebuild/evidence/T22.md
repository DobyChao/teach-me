# T22 · 动效收尾与拖动尺寸稳定

2026-10-19，用户反馈T21收尾偶闪、移动时诡异放大，并要求参考动画最佳实践。本任务验证全过程，不把T21的局部连续帧当作本轮通过证据。

## 定位与修复

Windows 11、Electron 44.7.2、本机125%缩放。先保留失败再修正：

- 强制原生视口先收紧、旧WAAPI结束帧延迟清理，原520→360过渡的背景实测249.23×14.96，目标应为360×74。旧背景按当前视口再次缩放。改为固定目标盒子的FLIP，终点identity，收紧前后均360×74。
- 拖动中注入+96的测高，旧缓存仍被修改，松手后75高变172。现在拖动中完全拒绝测高，模式/拖动边界提升panelLayoutVersion，释放后迟到的两代报告也拒绝；注入前后均360×75。
- 上述修复后，连续setPosition仍使75高累积到80。固定逻辑目标宽高，用setBounds只更新位置，不以取整回读作为下次基准；每档4个手势、每手势6次移动即时检查尺寸，不再累积或启动新形变。

参考与实现约束见[MOTION.md](../MOTION.md)、ADR-018。保留同HWND、单textarea、草稿/选区及减少动态效果；没有引入新动画库。

## Windows原生观察与范围

Computer Use对隔离dogfood实例执行原生鼠标拖动：mini两次、compose两次、conversation一次。mini截图保持120×48，原生回读120/121×49；compose截图360×74，原生361×75/76；conversation截图520×362，原生521×363。位置随手势变化，尺寸取整在1 DIP内，无连续增大；全过程同一HWND `320c3e0000000000`，compose焦点仍TEXTAREA。

随后恢复选择时测试实例已不在窗口列表；测试进程退出码0，runtime.log记录`shutdown: panel-quit`与正常quit。没有将它当成T14静置退出根因，也没有把后续尚未执行的原生收起动作记为通过。完整收起/展开和结束帧由上述实际Electron回归覆盖。

原生快照不保证观察到每个物理帧，结束时序由确定性故障注入补充。高刷新率、跨屏DPI、远控逐帧、IME/麦克风仍分别在原任务中待验；不据本轮宣称所有环境无闪烁。
