- Cursor：核对hooks与Cloud Agents API。stop返回followup_message属于收尾事件续跑；v1 create-run接口沿用既有云端Agent对话，忙碌返回409。本地IDE现有对话的外部投递入口尚未确认，不能把云端能力写成本地支持。
- GitHub Copilot：核对官方SDK/CLI兼容表，包含resumeSession、send默认enqueue、immediate和附件。受SDK控制的会话是接入候选；未验证对用户任意现有CLI/编辑器会话的连接可达性。

没有安装上述宿主、注册hook、发送消息或重启教学试用；没有改变App/CLI/skill运行代码。Codex本机help的历史核对来自T27，本轮没有用它冒称六种宿主实测。

## 结论与接续

产品维持Agent无关。统一消息/ack/消费者交接，由宿主适配层处理不同投递接口；skill只选择已验证的接收能力，没有适配器时仍用wait。按用户当前宿主和已有会话可达性选首个实验对象；本机Codex只是候选，不能把新建受控Agent当成复用当前Agent的验收。

尚未覆盖真实空闲唤醒、忙碌排队、附件投递、可靠ack、双消费者切换和结束停止；适配器保持未交付。下一步见tasks.json.nextUp。
