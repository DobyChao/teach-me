# T11 稳定任务栏入口与窗口复用

2026-10-17，Windows、Electron 44，codex/companion-rebuild-empty。

问题：主窗口还在时图标消失，快捷键又出现入口，看起来新开窗口。Electron 源码证实 SetFocusable 会连带 AddTab/DeleteTab；原代码在输入、设置和画布编辑中使用该接口但未恢复任务栏角色。

修复：宿主集中管理窗口输入与任务栏角色；主面板 APPWINDOW、非 TOOLWINDOW，画布反之；保留 NOACTIVATE 与其余样式。Electron 焦点切换后重申 Win32 样式与 taskbar 标记。样式更新用 SWP_NOACTIVATE/NOMOVE/NOSIZE/NOZORDER/FRAMECHANGED。输入异步等待后校验原 turn，取消或新 turn 不允许旧请求重新聚焦。HTML 始终不可聚焦、skipTaskbar。

验证：

- `node scripts/smoke.mjs` 24 项通过。新增连续三轮输入/取消、设置、画板编辑切换；实际读取 Win32 扩展样式，检查 APPWINDOW/TOOLWINDOW/NOACTIVATE；主面板和画布 HWND、renderer PID 均不变，browser-window-created 计数为 0。
- `node scripts/native-input.mjs` + computer-use 现场观察：合成绿色背景覆盖工作区、透明底部露出真实任务栏。闲置、原生 Ctrl+Alt+W 进入输入、真实键盘/Enter 发送成功之后，均有同一主任务栏入口；画布不在普通应用窗口列表出现。截图检查通过（面板排除、hide=0），CLI 回复已渲染且草稿清除。
- 初版只补调 setSkipTaskbar(false) 通过调用策略断言，却在现场发送结束后图标消失，因此放弃；加入 APPWINDOW 样式后重新执行以上完整验证。没有把调用断言当作任务栏视觉证据。
- `npm run check` 通过：规划、边界、格式、39 个测试、类型与构建全部通过。

限制：覆盖本机当前 Windows 任务栏与一次真实输入往返；未覆盖 Explorer 重启、其他 Windows 版本/第三方任务栏、长时间压力。没有提交测试截图或 runtime.log。此前本地日志记录 native-window-close，不能把这些退出归因为崩溃，也不能据此推断用户具体操作。
