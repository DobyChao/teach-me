# T52 · Ctrl+Alt+W 恢复中与录音被掐的反馈

2026-11-04。实现已进入本分支。任务保持 `in_progress`。Windows 真机未做。

## 文案（已进产品状态字段）

- 「正在恢复，稍等」：`recovery.hotkeyTip`
- 「这句没发出去」：`recovery.voiceTip`

面板用现有 `--busy`（状态）和 `--muted`（两句提示）。恢复 `complete` 后两句都清空。

## 本轮已验证

Node 夹具 `test/panel-recovery.test.ts`：

- 恢复中 `interceptTalk` 写入「正在恢复，稍等」，`decide('voice-start')` 为 swallow，测试里的麦克风标志保持 false。
- `complete` 后 hotkeyTip 为空，`interceptTalk` 返回 false，`voice-start` 变为 run。
- `begin(true)`（录音中）写入「这句没发出去」；`voice-stop` 与 `submit` 为 swallow，用户消息数组保持空。`complete` 后该句消失，消息数组仍为空。
- 空闲语音不会写「这句没发出去」。
- 旧 generation 不能在新的恢复上进行清掉这两句。

## Electron 夹具

recovery 模式会在 reload 完成前读取「正在恢复，稍等」。本环境 Linux 跑 `node scripts/renderer-recovery.mjs` 时，宿主在 Windows helper 启动失败（`NATIVE_SPAWN_FAILED`）处退出，没有执行到这条断言。不把这次运行记为通过。

## 未验证

过线必须在用户本机 Windows `LAPTOP-D1EFVD8K`，并附脱敏截图。四拍里仍缺真机：恢复中按 Ctrl+Alt+W 看到「正在恢复，稍等」且麦克风不开；录音被打断看到「这句没发出去」且对话没有假消息；恢复结束后提示消失，热键可以正常说一句。没有该证据不得标 done。
