# T36 · 断开连接请求的撤销

2026-10-20晚间。目标是让Agent在连接期间退出后可以重试，不留下无客户端取得凭据的活跃会话。与T34旧id attach竞态不同；本轮先处理有明确复现的连接可靠性问题，不重复无新增条件的T14静置实验。

## 复现与实现

独立调查先用当前HTTP处理函数和回环socket定位，再在3706bb4构建的真实Electron宿主上运行`node scripts/connection-cancel.mjs --baseline`：实际CLI子进程在start审批中被终止，旧审批仍可批准并创建ready会话，driver文件不存在；相同client重试被“已有活跃教学”拒绝。输出BASELINE_DEFECT，随后正常stop，退出0且endpoint删除。原始日志在忽略目录`.runtime/connection-cancel/1792506920629/result.log`。

宿主用HTTP响应的未完成close事件取消请求，撤销对应审批/选屏。start在原生input.cancel之后、创建Session前再次检查连接与退出状态，初次免审批secret在提交时才消费。attach撤销只清自己的审批，保留原Session。选屏动作每次等待后核对请求身份，防止旧点击恢复后批准新请求。没有更改30秒审批期限、CLI凭据格式或消息队列。

## 本轮实际验证

Windows本机、Node24.19.0、Electron44.7.2、工作区专用profile/client；真实CLI使用Electron自带Node模式运行。CLI返回凭据只在内存断言，不输出或提交。新夹具是`scripts/connection-cancel.mjs`与`test/desktop/connection-cancel.cjs`。

- 自动矩阵：start审批中终止CLI，审批及时撤回且无Session/driver；同client重试成功。正常start拒绝不建会话。
- attach审批中终止CLI，只撤回自身，原会话保持；正常拒绝不保存driver，正常批准仍绑定目标会话。
- 批准start后暂停真实PowerShell helper stdout，确认原生取消回包已积压；此时终止CLI再恢复helper，不创建或替换Session，随后可重试。
- 恢复后通过真实Renderer textarea输入/Enter事件，真实CLI wait取得完整文本并自动ack；再次wait为空，草稿清除。这里使用Electron注入输入，不冒称Windows原生键盘验收。
- `--display-race`：仅在测试进程模拟第二块显示器枚举，实际选择始终为真实屏幕；旧选屏动作在helper等待期间断连，新start进入选屏后恢复旧动作，新请求保持待决，明确新选择后才建立Session。未改系统显示器配置。

自动矩阵与选屏竞态均输出CHECKS_COMPLETE、退出0、删除endpoint。日志分别为`.runtime/connection-cancel/1792507100137/result.log`与`1792507453217/result.log`。两组回归加入现有Engineering checks；尚未推送或在远端执行，不能据此声称远端门禁通过。

独立审查者复核请求身份、取消监听清理及提交边界，未发现新增阻断问题；审查中提出的迟到选屏风险已修复并用上述竞态覆盖。最终`npm run check`通过84项测试、类型、构建、格式、边界与上下文检查（`.runtime/check-connection-cancel.log`）。在最终构建上重跑原T34 `connection-smoke`及本项默认/选屏两组均通过，输出完成标记、退出0并清除endpoint；日志为`.runtime/connection-smoke-final.log`、`connection-cancel-final.log`、`connection-display-race-final.log`。没有重复旧构建复现。
