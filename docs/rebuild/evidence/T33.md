# T33 · Windows辅助进程代次隔离与故障诊断

2026-10-20。起因：T32最终回归中一次首次启动inputPolicy等待约10秒失败，仅有同一“无法应用窗口任务栏样式”提示；当时没有helper代次/退出/超时诊断。现场原因仍未知，不因为时长相符直接归因。

独立调查用当前类配合内存子进程替身，确认dispose后旧exit清空新pending/child，以及旧stdout半行拼入新child响应两项确定缺陷。它们需要helper更替，尚无证据对应这次首次启动失败。

目标A37：每代pending与输出缓冲独立；dispose/退出/超时及时结算自己的请求，旧事件不影响新helper；超时实例作废，下一次请求可新建，但不自动重试可能已执行的窗口操作。固定错误码及安全事件区分spawn/exit/write/timeout/协议错误/native拒绝，原始stderr/命令/句柄不进入日志。真实Windows helper退出后能重新执行本应用窗口策略。

当前实现和验收待完成。

## 实现与验证

- 三项旧实现行为测试实际全部失败；修复后通过。追加共12项覆盖spawn同步/异步失败、exit、stdin同步/异步失败、原生False、协议错误、10秒虚拟超时、旧事件隔离、ready/stderr字节统计与日志无原文/句柄、report抛错隔离；均通过。
- `node scripts/native-helper-smoke.mjs`：真实PowerShell握手和本应用窗口NOACTIVATE/APPWINDOW样式有效；真实helper被终止时pending以NATIVE_HELPER_EXIT失败，下一次请求新建helper并恢复样式；dispose及时返回NATIVE_DISPOSED后再次创建成功；无效句柄返回NATIVE_POLICY_REJECTED。夹具只操作自己的窗口，三个helper均等待退出。
- 新构建的`renderer-recovery.mjs --interactive`再次通过：实际renderer崩溃后，原生鼠标聚焦、键盘输入、Enter发送，夹具确认清稿、wait/ack及同profile重启。没有通过mock窗口操作替代该观察。
- 独立审查未发现新的阻断问题。所有错误测试原文/测试句柄只用于内存替身，不进入产品日志。

## 简短进展与边界

本轮交付helper更替可靠性和可用诊断，没有修改系统设置或额外安装后台服务。首次启动偶发10秒失败的原因仍未确认，T14继续保留；今后可依据native-request-failed的reason/ready、helper-ended的exitCode/stderrBytes缩小原因，不再把所有失败归为同一句窗口样式错误。真实冷启动慢/系统资源紧张/安全软件干预尚无复现证据，不推测为已确认原因。
