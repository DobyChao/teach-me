## 后续优化顺序建议

以下是后续候选范围，不代表已交付的新功能；正式任务状态仍仅在 tasks.json。

1. **先稳定常用链路**（T02/T10/T14/T17）：继续围绕连接、输入、收发、切换做真实体验回归。让用户随时知道 Agent 是否在监听、消息是否已投递，以及失败后能做什么。退出根因未复现，仍需依赖诊断证据。
2. **画板收尾体验**（T15）：工具已经充足，优先评估显式本地保存/打开、PNG导出，以及离开/退出前的内容生命周期提示。当前只在运行内存保留；是否自动保存、保留多久、如何清理须先形成产品决议，再改实现。本轮没有重启丢图实验，内存生命周期来自现有实现和 ADR-011。
3. **长回复更易读、设置更易返回**（T02/T06）：消息目前按纯文本渲染，可评估列表/代码呈现与便捷取用；设置保存/返回可固定在可见位置，避免来回滚动。不要因此继续增大默认输入面。
4. **补齐输入真实性**（T03/T06/T07）：原生IME、麦克风设备释放、真实外部软件焦点和不同缩放多屏优先于继续微调视觉。测试通过和真机覆盖分别记录。

## 可重复体验

构建后 `node scripts/dogfood.mjs` 启动隔离应用并建立合成会话；CLI 指向 `TEACH_ME_AGENT_HOME=<repo>/.runtime/dogfood` 并使用 `--client dogfood`。`--verify` 运行自动流程后退出。结束手动体验用同目录的 CLI `stop --client dogfood`，再重新运行，避免同一测试目录并发实例。
