# T20 · 过渡与独立设置窗口

2026-10-19。按用户两项体验反馈实施；自动回归、原生观察与未验证项分别记录。

修改前现有panel-modes六组回归通过，说明已有原生尺寸插值，不能据此否定用户的“没有过渡”感受。代码中模式结束后的ResizeObserver测高走直接setBounds，目标布局也即时切换；本轮覆盖测高/重定向的连续性并检查实际画面。

## 实现与边界

- 三档使用280ms cubic ease-out，目标内容以目标宽度布局，背景随实际窗口尺寸变化；当前档位重新测高也从当前帧继续，重复目标不重启动画。保持同一HWND和textarea；不通过隐藏/重显实现过渡，减少动态效果仍直接切换。
- 设置预建为一个独立普通BrowserWindow，重复打开复用，关闭隐藏；不替换对话，不改主面板尺寸，保留消息草稿/选区/阅读位置。标题使用系统边框，正文滚动，保存/取消固定底部。
- 设置异步保存，写盘成功后才更新运行配置；失败保留表单并显示错误，不把局部保存错误写成主面板全局错误。设置打开时抑制输入准备的晚聚焦；关闭后恢复原输入焦点。
- 固定preload与sender校验：设置sender仅允许settings/settings-focus/select-display，不能prepare/quit/画板操作；内容保护和自身取图排除覆盖新窗口。

## 现场发现与失败尝试

1. 将高度测量纳入过渡后，旧mini/dogfood检查在100ms内读布局，会读到合法动画中间帧并报裁切。改为有上限的静止等待后重跑通过，不能把旧时序断言直接当成渲染缺陷。
2. 普通设置窗口第一次show时出现收到focus事件但isVisible=false、系统列表没有该窗口；原生入口和回归均复现。最小独立窗口实验比较普通/owned窗口，首个普通窗口复现；增加可见性检查及showInactive回退后实验与最终入口通过。Windows启动信息影响首次ShowWindow的机制有官方说明（ADR-016链接），具体启动器关联仍属推断，与历史T14进程退出不是同一已证实原因。
3. 原生标题栏鼠标拖动先后在owned实验和最终普通窗口共三次未造成位置改变；没有充分证据判断应用标题栏问题还是自动化非客户区坐标/输入问题。不能将此记为通过。最终普通窗口的系统菜单显示移动可用，经Alt+Space、M、Right、Enter，原生x从704变715，说明系统移动路径可用；这不代替鼠标拖动验收。

## Windows原生观察

使用Computer Use控制隔离dogfood实例，单屏125%缩放。测试配置关闭消息截图附件并允许测试窗口被捕获，禁用快捷键注册；没有改正常实例配置、隐私选项或启用麦克风。

实际点击小胶囊写字入口，看到展开中间画面。16ms原生尺寸采样在同一窗口记录宽度120→170→215→259→296→310→332→346→351→358→360，高度49→75；采样约292ms完成。随后通过原生点击展开到大号，输入的合成草稿仍可见；该观察只证明本机单屏这条路径。

实际设置入口弹出独立窗口，系统标题为“Teach me, Agent · 设置”，底部取消/保存完整可见。主面板打开前后保持360×112、同一HWND；系统菜单移动后的设置窗口仍可正常显示。原生Alt+F4关闭后，设置hidden，主面板保持原尺寸、input=editing、焦点回到TEXTAREA。最后在最终构建上重新点击胶囊/更多工具/设置并关闭，再次观察同样的恢复结果。销毁的只是自己的隔离实例。
