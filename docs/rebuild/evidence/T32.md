# T32 · 主面板渲染进程崩溃后有界恢复

2026-10-20。Windows 11 / Electron 44.7.2 / Node 24，独立profile。

## 基线与目标

当前主进程只记录render-process-gone。独立夹具对panel执行forcefullyCrashRenderer后，面板isCrashed且未重新完成load，API/session仍在线，重复启动提示已有实例并退出0；正常stop后同profile可重启。原始T14静置退出根因仍未知，不能把故障注入当成其根因。

验收目标A36：仅重载panel本地UI，同HWND保留session和未ack消息，取消旧输入/语音/待审批；明确未发送稿可能丢失。60秒内最多一次自动恢复，重复故障/重载失败/10秒超时走有界清理并退出1，可手动重启；健康overlay及HTML内容不自动重载。

实现、运行结果与独立审查待补，当前不声称通过。

## 实现与实际验证

- 首次真实崩溃后原HWND重载，历史与未ack id保留；旧turn明确拒绝，新turn可以投递且清稿，wait/ack读到新消息一次。重复启动仍指向同host。
- 60秒内第二次真实崩溃不重载，退出1；分别注入loadFile拒绝与永不完成，真实10秒恢复期限生效并退出1；每种故障后endpoint清理、同profile重启均通过。普通stop/重启也通过。
- 同时待处理的capture ask与attach均在崩溃时拒绝，恢复后请求状态为空。恢复重载期间触发注册的快捷键回调，不覆盖恢复提示。
- 真实Excalidraw矩形经Electron鼠标事件创建；panel单独崩溃后overlay PID、画板epoch/count以及导出PNG的SHA256相同。属于实际Electron功能回归，不冒称本轮原生鼠标画板验收。
- `--interactive`：Windows原生鼠标点击恢复后的唯一输入框、输入测试消息并按Enter；夹具确认投递、清稿、wait/ack、正常退出及同profile重启。界面恢复和可用输入已直接观察；本轮未评估逐帧崩溃过渡观感。

## 审查发现与失败记录

独立审查发现旧语音review提交迟到拒绝会取消恢复后的新录音/输入；行为测试在旧实现实际失败，按generation忽略旧失败后6项语音测试通过。审查另指出恢复中的快捷键可覆盖恢复提示，已忽略恢复/退出期间及跨恢复代次的快捷键。

追加附件挂起实验复现：恢复后新turn已准备，旧附件失败仍覆盖新的UI错误。修复IPC错误回调的恢复代次隔离。首次尝试在Renderer替换export函数因返回函数不可克隆失败；改为void后又因React每次state更新重建export而未命中。最终在宿主延迟真实overlay执行，明确到达导出门闩，旧构建以实际error不为null失败；这两次夹具失败未计为产品复现。

## 边界与简短进展

本轮只保证panel renderer的有限恢复；主进程、GPU、overlay、settings单独崩溃以及长时间跨屏仍pending。主进程终止时会话为内存态，不承诺跨进程保留。没有自动重新执行HTML，没有持久化草稿或额外后台服务。T14静置退出仍独立追踪。最终完整检查和追加回归结果收尾时补齐。

追加结果：迟到IPC原场景在修复构建通过，完整恢复/正常stop、重复崩溃、重载拒绝、重载挂起及各次重启通过。独立审查最终未发现新的阻断项。一次最终重跑在启动阶段WindowsAdapter.inputPolicy等待约10秒后失败退出1，尚未到崩溃注入；后续进程检查无该失败host残留helper，重跑完整场景通过。该启动超时保留为独立待诊断问题，不能用重跑通过抹去。
