# T34 · 加入审批绑定申请会话

2026-10-20，Windows / Electron 44.7.2 / Node 24。本轮将错误会话路由置于布局完善之前；这是既有R05审批边界的修复，不引入新的消费者或宿主适配架构。

## 复现、原因与修复

`node scripts/connection-smoke.mjs --baseline`在修复前构建中实际复现：结束旧会话，新start获批准后暂停真实PowerShell helper的stdout，使input.cancel尚未完成；此时旧id的attach仍进入审批。恢复helper后新会话建立，再批准旧attach，返回200且id/token属于新会话。夹具只输出匹配结论，不输出凭据。原因是attach只在审批前核对id，批准后读取全局session，而且允许对ended目标申请。

最小修复将申请时Session绑定为局部对象，审批前拒绝ended，批准后再次检查对象身份和活跃性，最后仅返回该对象的凭据。正常审批行为不变。

## 本轮验收

- `node scripts/connection-smoke.mjs`：真实Electron、真实loopback HTTP和原生helper延迟；正常批准/拒绝、结束目标不审批、旧目标与新start交错、审批期间结束后批准不返回凭据均通过。之后新建/加入会话、真实IPC提交、wait/ack及正常退出通过。
- `node scripts/connection-smoke.mjs --interactive`：Windows窗口现场显示申请主题和允许/拒绝按钮，原生鼠标点击允许连接，随后同一夹具全部检查通过并退出0。首次交互尝试超过既有30秒审批期限，工具点击时窗口已退出而失败；刷新并及时重跑通过，没有修改产品期限。
