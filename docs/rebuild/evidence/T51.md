# T51 · RECOVERING 中撞控件不得整 App 退出

2026-11-04。实现已进入本分支。任务保持 `in_progress`。Windows 真机未做。

## 实现

同一条 A36 面板恢复路径。RECOVERING 期间发送、取消、设置、画板、关闭（`quit` / `end`）和语音开始等主控件在 host 被吞掉，返回当前快照，不调用 `shutdown`，也不结束 session。面板原生 close 在恢复期间同样不退出。快照 `recovery.status` 为「正在恢复」，面板常显这句并禁用控件。失败、超时，或 60 秒内第二次恢复，状态文案是「面板恢复失败，请重新打开。」，控件仍保持吞掉直到进程按原有界路径退出。恢复成功后清空这句，并保留原来的「面板已恢复。未发送的草稿或录音可能丢失，请重新输入。」

## 本轮已验证

Node 夹具 `test/panel-recovery.test.ts`（`node --test`，6 项通过）：

- 注入 RECOVERING 后连点 `submit` 5 次，再派发 prepare / submit / cancel / continue / settings / settings-focus / edit / quit / end / voice-start / voice-stop 等：全部 `swallow`，quit 与 end 的执行次数为 0。
- `recovery.status` 为「正在恢复」。
- `fail` 与 60 秒窗口内第二次 `begin` 的 status 为「面板恢复失败，请重新打开。」，quit 仍 swallow。
- 旧 generation 的 `complete` / `fail` 不能清掉或覆盖当前恢复。

这是可注入的状态机夹具，不是 Windows 进程或 HWND 观察。

## Electron 夹具

`test/desktop/renderer-recovery.cjs` 的 recovery 模式在真实 reload 返回前断言 DOM「正在恢复」、热键文案「正在恢复，稍等」，并连点 submit / cancel / settings-focus / edit / quit，要求 session 与窗口仍在、被吞掉的发送不进消息。恢复结束后再等「面板已恢复」，并要求「正在恢复」和「这句没发出去」从界面消失。

本环境是 Linux。运行 `node scripts/renderer-recovery.mjs` 时宿主在应用窗口样式阶段退出，错误为 `NATIVE_SPAWN_FAILED` / 「无法应用窗口任务栏样式」，进程退出码 1，没有进入崩溃注入。因此这次运行不能当作该夹具通过，也不能当作 Windows 证据。
