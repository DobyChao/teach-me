# T43 · say/show组合wait削减CLI进程往返

2026-10-23。用户反馈响应太慢：每个教学步骤末尾的`show`与重新`wait`是两次Node进程冷启动，Windows上各100–300ms。目标：`tma say/show`支持`--wait [--timeout 秒]`，同一进程内交付、打印、自动ack，输出单个JSON `{delivered, messages, ended, timeout}`；非法timeout在交付前拒绝；不改变打印先于ack的重投递语义，不新增第二wait消费者。

实现仅改`bin/teach-me.mjs`：布尔flag表加`wait`；抽出`waitSeconds`（复用1–480秒校验，组合时在交付前先校验）、`printThenAck`（原wait的打印后ack逻辑原样迁移）与`deliverThenWait`；`say`/`show`带`--wait`时交付后立即长轮询并输出合并JSON。wait命令行为不变。宿主HTTP层无改动：组合命令复用既有/say、/show、/wait、/ack路由。

验证：新增`test/cli-deliver.test.ts`以fixture HTTP端点spawn真实CLI进程，覆盖四条：say --wait的交付→wait→ack顺序、请求体（text、timeoutMs=5000、ack id）与合并输出形状；show --wait的场景透传、默认480秒与drawn结果；不带--wait时只有/say一次调用不轮询不ack；`--timeout 0`在发出任何请求前失败退出1。4项通过，npm test 119+4项通过。帮助文本与AGENT-PROTOCOL、SKILL同步说明输出形状、不得与单独wait并发、交付与接收非事务（整条重跑会重复交付say/show）。

边界：本项只削减进程往返，不改变LLM或截图审批耗时；fixture端点不代表真实Electron宿主，但组合命令不涉及宿主改动，风险在CLI侧已由真实进程覆盖。实机收发随T44的实机验证一并观察。
