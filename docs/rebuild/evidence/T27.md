# T27 · 主动capture与原生唤醒优先的skill规则

2026-10-19。用户结束快速试用，反馈主动capture不足，要求wait为兜底并研究宿主hook/唤醒。试用子代理已报告ended=true并停止，本轮不重新连接或抓取用户桌面。

## 变更与依据

原skill将“优先用户图”和“回复后回到wait”写成固定循环，capture仅附带一句。现按视觉证据与接收策略分层：视觉任务由Agent主动取当前画面，足够新的用户图可复用；指错/新弹窗/结果未知时重新观察，小图标zoom，不在超时或固定间隔抓屏，不绕过拒绝。

接收优先已配置且经过同会话端到端验证的原生桥，否则wait。当前代码仍只有Session队列、wait、ack，capture返回shot.path；没有外部唤醒适配器。原生能力研究、官方来源和可靠接收契约见[HOST-INTEGRATION.md](../HOST-INTEGRATION.md)，T28尚为todo。未修改App、宿主hook或模型配置。

本机Codex帮助核对为0.163.0-alpha.10.2，queue命令存在；没有向任何真实对话调用queue。普通async hook不自动开启新turn、Claude Channels/asyncRewake与OpenCode session.prompt等差异来自所链接官方文档；候选接口存在不是TMA已接通的证据。

## 案例规则审阅

以下为人工阅读skill后的预期路径核对，不是独立Agent执行记录：

| 场景 | 修订后的规则 |
| --- | --- |
| 首次教屏幕操作，没有相关新画面 | capture→打开shot.path→选择控件/指引 |
| 用户消息已附当前相关截图 | 打开全部shots.path并复用，不重复取相同证据 |
| 用户文字说完成，但操作可能打开了新界面 | 主动capture确认新状态，不把done当作视觉证明 |
| 用户说指错/图标太小 | 重新取当前画面，需要时zoom，核对后再改指引，不盲猜旧坐标 |
| 纯概念问题/长等待超时 | 不为凑流程取图，正常回答或继续接收 |
| 截图拒绝或取消 | 不循环申请，不伪称已看到当前界面 |
| 宿主有hook但没有TMA桥 | 仍用一个活跃wait，不退出后假设能被唤醒 |
| 存在已验证同会话原生桥 | 按桥的投递/ack路径处理，不再开第二个长等待；真实链路待T28实测 |
| 用户停止/ended | 停止收取，不重新连接；本轮试用子代理已报告ended=true |
